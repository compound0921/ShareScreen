# ShareScreen

Windows 屏幕共享。本机采集画面,别人用浏览器打开链接就能看,不需要装任何客户端。

> 发布件是**一个文件夹**:程序本体、`tools/` 里的两个组件、一份 `使用说明.txt`。
> 整个文件夹解压出来保持原样就能跑,机器上不用装任何东西。见[发布](#发布)。

---

## 准备(只有自己编译时才需要)

**用发布包的人这一节整节跳过** —— 解压出来的文件夹里已经带着这两个组件了。

从源码编译才要自己下。程序依赖两个第三方组件,都是免安装单文件,下载后按
下面的路径放好:

| 组件 | 下载 | 放成 |
|---|---|---|
| **ffmpeg** | [gyan.dev](https://www.gyan.dev/ffmpeg/builds/) 选 `ffmpeg-release-essentials.zip` | `tools/ffmpeg/bin/ffmpeg.exe` |
| **MediaMTX** | [GitHub Releases](https://github.com/bluenviron/mediamtx/releases) 选 `mediamtx_v*_windows_amd64.zip` | `tools/mediamtx/mediamtx.exe` |

压缩包里带的版本号文件夹重命名成 `ffmpeg` / `mediamtx` 即可。

> 这两个文件既是编译的输入,也是发布的内容 —— `genrelease` 会把它们原样
> 拷进发布文件夹。换 ffmpeg 版本就是换这一份文件。

## 运行

双击 `sharescreen.exe`。浏览器会自动打开控制页,任务栏托盘出现一个图标。

程序没有窗口,运行期间靠托盘操作:

| 操作 | 效果 |
|---|---|
| **双击图标** | 打开控制页 |
| 右键 → 打开控制页 | 同上 |
| 右键 → 开始 / 停止共享 | 不用切到浏览器 |
| 右键 → 退出 | 停止共享并退出 |

**关掉控制页 = 关掉程序。** 页面和程序之间挂着一条长连接,页面一关连接就断,
程序随即退出(等 3 秒,刷新页面不会误判)。所以别随手把标签页关了 —— 关的时候
正在推的流会一起停。反过来,切到别的标签页、锁屏、合盖都不会断,不影响。

> 只有**开过**控制页才这么算。用 `-no-browser` 启动、或者浏览器压根没打开过,
> 程序会一直在托盘里待着。

日志写在 `%LOCALAPPDATA%\ShareScreen\sharescreen.log`,每次启动覆盖。

### 端口被占用时

启动时如果端口被占用,程序不会直接退出 —— 那只会让你看到"闪退",而且不知道
下一步该做什么。它会按情况处理:

| 情况 | 行为 |
|---|---|
| 已经开着一个 ShareScreen | 直接打开那个实例的控制页,然后退出 |
| 占端口的是自家残留进程(mediamtx / ffmpeg) | **自动结束它,不问**,然后继续启动 |
| 占端口的是别的程序,且是本地端口 | 问你要不要换个端口(会写进配置) |
| 占的是 WebRTC 播放端口或媒体端口 | **不自动换**,说明该怎么做然后退出 |

> 残留的 mediamtx / ffmpeg 直接清掉是有意不弹框的:它本来就是你上一次没退
> 干净的进程,此刻唯一的作用就是挡路,没什么可选的。结束它之后 WebRTC 那两个
> 端口也就空出来了,路由器映射不用动。
>
> 是别的程序占着端口,那才是有代价的决定 —— 那种才会问你。

**WebRTC 那两个端口不做自动更换。** 它们在路由器上做了映射,换了等于把公网
入口挪走 —— 观众直接连不上,而你要等到别人反馈才会发现。这种事不能悄悄做,
所以程序只把该做什么讲清楚,换不换由你决定。

> 判断"是不是自家进程"看的是**可执行文件的完整路径**,不是进程名 ——
> 你自己开着的 ffmpeg 不会被误杀。
>
> 询问框的默认按钮是**否**(换端口那个框)。顺手按回车不会把端口改掉。

改过端口之后,记得同步改路由器上的端口映射。

## 使用

### 1. 选采集源

| 选项 | 说明 |
|---|---|
| **屏幕(推荐)** | GPU 采集,CPU 占用最低,支持 60fps。不支持单窗口 |
| 屏幕(兼容模式) | 通用兜底,但帧率明显更低 |
| 单个窗口 | 从列表里选。**窗口被遮挡时画面会被遮挡物盖住** |
| OBS 虚拟摄像头 | 画面来自 OBS,声音来自桌面音频(勾了才有)。虚拟摄像头是纯视频设备,OBS 的混音不跟着它走 |
| OBS 直推 | 画面和声音**全都由 OBS 提供**。需要多来源叠加、加滤镜、做转场时用 |

### 带声音

**默认就开着。** 勾选「共享桌面音频」后,观众听到的是**你扬声器里正在放的声音**
—— 程序直接抓默认播放设备,换耳机、切 HDMI、插蓝牙都自动跟随,不需要改任何
系统设置。

> ffmpeg 自己采不到桌面音频(没有 WASAPI 输入设备,声卡也普遍不再提供
> 「立体声混音」),所以这部分是程序自己调的 WASAPI 回环。
>
> 声音固定用 Opus 编码,这也是推流走 RTSP 而不是 RTMP 的原因:RTMP 只能带
> AAC,而浏览器的 WebRTC 不认 AAC,MediaMTX 又不做转码。

采不到时(没有播放设备、被系统隐私设置拦住)程序会**退化成无声画面**,
并在控制页给一条提示 —— 不会因此起不来。

> ⚠️ **观看链接末尾的 `?muted=0` 不能丢。** MediaMTX 自带的播放页默认把
> `<video>` 设成静音,不带这个参数就是"画面正常、一点声音没有",很容易被
> 误判成音频链路坏了。程序生成的链接已经自动带上了。
>
> 如果画面没有自动开始,点一下播放键 —— 浏览器不允许带声音自动播放。

#### 想连 OBS 的混音一起推

用 **「OBS 直推」**,让 OBS 把画面和声音一起推过来:

1. 控制页把采集源切到 **「OBS 直推」** —— 上面会出现一个推流地址
2. OBS → 设置 → 直播:服务选 **WHIP**,地址填 `http://127.0.0.1:8889/live/whip`
3. 确认 OBS 的**「混音器」里有「桌面音频」**
4. 点 OBS 的「开始推流」

这时本程序不运行 ffmpeg,只负责把流分发出去。开关在 OBS 那边,控制页上的
开始/停止按钮会隐藏;分辨率、帧率、编码器也都改在 OBS 里设。

> ⚠️ **必须用 WHIP,不能用 RTMP。** OBS 走 RTMP 推的是 AAC,浏览器收不了。
> WHIP 走的就是 WebRTC,OBS 发 Opus,原样透传。WHIP 需要 OBS 29 或更高。

### 2. 调参数

分辨率、帧率、码率、编码器、音频都能改,默认 `原始分辨率 / 60fps / 3 Mbps + 96kbps 音频`。

界面上实时显示**当前设置能支撑几个观众**,算法是 `上行带宽 × 0.7 ÷ (视频码率 + 音频码率)`。

> **上行带宽是最硬的约束。** 每个观众占一路独立码率,超出后不是排队,是所有人一起卡。
> 填**实测**的上传速率,不是套餐标称值。
>
> 画质不够时**优先降分辨率,别降帧率** —— 码率固定时帧率翻倍等于每帧比特数减半。

改参数会重启采集进程,观众侧黑屏约 1–2 秒。

### 3. 点「开始共享」

把观看地址发出去,或者让对方扫码。

## 观众怎么看

打开链接就行,不需要装任何东西。

> ⚠️ **播放路径不做鉴权 —— 链接本身就是凭据。** 谁能打开链接谁就能看,别发到公开场合。

## 远程控制

在观看之外,还可以让对方**经你同意后操作这台电脑**(鼠标、键盘、剪贴板文本)。

在控制页右栏勾上「允许远程控制」,下面会出现一条**可控制链接**(带二维码),
发给对方即可。对方点「申请控制」,你这边会跳出批准提示,点了「允许」他才能动。

- **默认关闭。** 不开的时候程序不会多监听任何端口,路由器上也不会多开映射 ——
  不开启就没有任何多余的对外入口。
- **两层门槛。** 链接里的凭据决定能不能连上来,主机的当场批准决定能不能操作。
  即便链接泄露,陌生人也只能看、不能动。
- **随时可收回。** 控制页和托盘菜单里都有「收回控制权」。
- **明文传输**,和观看链接一样 —— 对方在你机器上敲的东西会以明文经过网络,
  不要在不可信的网络里开启。
- 只有**整屏采集**能远控。窗口采集和 OBS 不行 —— 它们没有稳定的屏幕坐标。

控制不了的地方(都是 Windows 的设计,不是故障):锁屏界面、UAC 弹窗、
Ctrl+Alt+Del;以及当前窗口以管理员身份运行时(控制页上会提示原因)。

剪贴板同步是单独的开关,默认关着,只和正在控制的那个人同步。
原理和实测数据见 `docs/架构设计.md` §12。

## 让公网也能看

有两条路。**先试第一条,它只用勾一个复选框。**

### 省事路线:让程序自己去开端口

控制页勾上 **「自动配置路由器端口映射(UPnP)」**。程序会自己找到路由器、
把两条映射建好,并把拿到的公网地址填进观看链接。之后公网 IP 变了它会自己跟上。

前提是路由器开着 UPnP(多数家用路由器默认开着,华为/小米/华硕的管理页里叫
「UPnP」或「通用即插即用」)。走这条路时:

- 公网端口**内外一致**(8889、8189),所以链接形如 `http://<公网IP>:8889/live/`
- **不必**再去路由器后台做任何事
- 但 **Windows 防火墙仍然要放行** 8889/tcp 和 8189/udp —— UPnP 开的只是路由器
  那扇门,系统防火墙这道它管不着。程序在状态行里也会提醒你这一条

用不了的情况(状态行会直说卡在哪一步):路由器关着 UPnP、在**运营商级 NAT**
后面(光猫拿到的是 100.64.x.x 这类地址)、或者双重 NAT。这几种情况下自动映射
帮不上忙,只能走下面的手动路线,或者改用 VPS 中转(见[公网部署手册](docs/公网部署手册.md))。

想单独排查是哪一步不通,跑:

```bash
go run ./cmd/portmapcheck            # 只读:看看发现到路由器没有、外网地址是什么
go run ./cmd/portmapcheck -map       # 试建一次映射,试完自动删掉
```

### 手动路线:自己进路由器配

**第一步:路由器加两条端口映射**

| 名称 | 协议 | 外部端口 | 内部 IP | 内部端口 |
|---|---|---|---|---|
| ShareScreen-WHEP | TCP | 8443 | 本机内网 IP | 8889 |
| ShareScreen-ICE | **UDP** | 8189 | 本机内网 IP | 8189 |

- ⚠️ UDP 的内外端口**必须都是 8189** —— MediaMTX 在 ICE 候选里写死了它,改了就连不上
- ⚠️ **不要映射 1935**(推流端口),映射出去等于让任何人都能覆盖你的画面
- 记得同时放行 Windows 防火墙的 8443/tcp 和 8189/udp

**第二步:控制页「公网地址」填** `<公网IP或域名>:8443`

填完会自动重建配置,几秒后生效。**不填的话公网观众拿到的全是内网地址,画面出不来** —— 症状是页面能打开、播放器一直转圈。

> 手动填进去的地址**程序不会去改** —— 用了 DDNS 域名的话,域名本身不会变,
> 改了反而错。只有留空、或者上一次是程序自己填的,它才会自动覆盖。

**第三步:用手机开 4G 验证**

一定要关掉 WiFi。走 WiFi 是在局域网内访问,测不出公网链路的任何问题。

## 停止

托盘图标右键 → 退出。ffmpeg 和 MediaMTX 会一起退出,不留残留进程。

关掉控制页也一样 —— 两条路都走同一套收尾流程,不区分。

**例外:远程控制开着的时候,关控制页不退程序。** 远控的典型用法是人不在电脑前,
浏览器标签崩溃或被误关会把整个程序连带杀掉,而那时你没法重启它。这种情况要退出
请走托盘菜单。

## 构建

需要 Go 1.27+。国内建议先 `go env -w GOPROXY=https://goproxy.cn,direct`。

先按[「准备」](#准备只有自己编译时才需要)把两个组件下好 —— 编译要用到它们,
但不再嵌进 exe,而是留在 `tools/` 里。

```bash
go build -ldflags "-H=windowsgui -s -w" -o sharescreen.exe .
```

产物 **8 MB** 左右,一秒编完。运行靠的是 exe 旁边的 `tools/` 目录,所以在源码
目录里直接跑没问题(`go run .` 也会去当前目录找);编完拷到别处就得连 `tools/`
一起拷 —— 发布时用 `genrelease` 打成一个文件夹,见下。

> `-H=windowsgui` 是去掉控制台窗口的关键,不加的话每次启动都会弹黑框。
> `-s -w` 只去符号表,不影响功能。

**关于图标:** `rsrc.syso` 是 exe 的图标资源,已生成好放在仓库里,`go build`
会自动链进去 —— 不需要额外工具,也不用改构建命令。改了图标定义
(`internal/icon/icon.go`)之后跑一次 `go run ./cmd/genicon` 重新生成即可
(加 `-preview 目录` 可以把各尺寸导成 PNG 看效果)。

### 发布

```bash
go run ./cmd/genrelease -version 0.1
```

产出在 `dist/`:一个 `ShareScreen-1.2.zip`(约 70 MB),解压出来是

```
ShareScreen-1.2/
  ShareScreen.exe                  程序本体,8 MB
  使用说明.txt                      给用户看的那一页
  tools/ffmpeg/bin/ffmpeg.exe      采集和编码
  tools/mediamtx/mediamtx.exe      WebRTC 分发
```

发给别人就把整个 zip 发过去,让对方解压后直接双击文件夹里的 exe。

> **为什么发文件夹,不发单个 exe。** 早先有一版把两个组件嵌进二进制,编出来是
> 一个 165 MB 的单文件,拷到哪都能跑 —— 但它把 ffmpeg 和 MediaMTX 藏进了 exe 里。
> 用户看不见里面装着什么,组件版本对不上时既换不掉也说不清,出问题时连"到底
> 跑的是哪份 ffmpeg"都无从确认。现在三样东西各归各位,换组件就是换 `tools/`
> 里的文件。
>
> 仍然要打成 zip:两个组件合计 155 MB 且基本压不动,能压下去的只有程序本体
> 那 8 MB,打完大约七折。

`使用说明.txt` 的来源是 [docs/使用说明.txt](docs/使用说明.txt),打包时会转成
UTF-8 BOM + CRLF —— 它只会被双击打开,也就是用记事本,而老版本记事本认不了
无 BOM 的 UTF-8,也认不了 LF 换行。

`go run ./cmd/genrelease` 的 `-version` 只是写进文件名,留空则用当天日期。
